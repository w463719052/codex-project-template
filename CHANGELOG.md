# Changelog

All notable changes to the formally versioned project template are recorded
here. Template versioning follows semantic versioning for generated-contract
compatibility; repository commits remain the detailed source history.

## 2.0.0 - 2026-08-26

- Replace the universal pre-edit approval round trip with conservative L1-L4
  authorization: direct bounded L1 execution, once-approved L2 directories, and
  exact L3/L4 plans with protected boundaries retained at every level.
- Make the default render a focused core preset; keep the full preset and exact
  include lists for evidence-selected architecture, ADR, shared-library,
  performance, and skill-design artifacts.
- Expand the rules log to suggest evidence-backed workflow adjustments after
  three explicit recurring operator choices, with no persistence or rule
  synchronization before confirmation.
- Add a dependency-free paired real-task A/B analyzer for first-pass success,
  user round trips, elapsed time, optional token telemetry, scope escapes, and
  review defects without treating example data as performance evidence.
- Make `CODEX_WORKFLOW.md` the sole full authorization state machine; reduce
  `AGENTS.md`, usage, task-record, and change-impact templates to distinct
  entrypoint, example, field-recording, and L3/L4 worksheet responsibilities.

## 1.3.0 - 2026-08-26

- Add a C engineering profile grounded in ISO/IEC 9899:2024 and SEI CERT C,
  including API boundaries, header hygiene, ownership, cleanup, integer safety,
  concurrency, portability, static analysis, sanitizers, and fuzzing guidance.
- Add a Web Frontend profile for HTML/CSS, Sass/Less, JSX/TSX, Vue, Svelte,
  Astro, and common frontend build markers, covering semantics, component/state
  ownership, accessibility, browser lifecycle, security, performance, and tests.
- Keep header-only repositories ambiguous across C, C++, and Objective-C until
  stronger source or project evidence is available.

## 1.2.0 - 2026-08-26

- Add reviewed engineering profiles for Swift, Objective-C, Kotlin, Java,
  TypeScript/JavaScript, Python, Go, Rust, and C++ with primary-source provenance.
- Add a deterministic read-only language-profile selector based on repository
  path/build evidence, including explicit ambiguity reporting.
- Make the selected industry baseline the preferred standard for new and
  materially changed code while preserving verified hard constraints.
- Add engineering guidance for architecture, pattern fit, naming, nesting,
  function/file decomposition, errors, concurrency, resources, and tests.
- Add a coding-rules log and promotion workflow for repeated manual corrections,
  with separate approval for enforcement configuration or historical migration.

## 1.1.0 - 2026-08-25

- Add machine-readable project maps, context routes, and verification routes.
- Add read-only Context Pack and command-selection scripts with strict schemas,
  path safety, deterministic budgets, and no execution authorization.
- Add performance guidance, stable rule IDs, routing benchmarks, fixtures, and
  regression tests while preserving focused-render compatibility.
- Add structured JSON placeholders and post-render schema validation.

## 1.0.0 - 2026-08-25

- Establish a mandatory investigate/propose/approve/execute/reapprove/verify
  workflow with no direct-execution exception.
- Add architecture, module, coding, change-impact, ADR, shared-library, and
  library-documentation templates.
- Add collision-safe deterministic rendering with a versioned state manifest.
- Add structural validation, unit tests, and repository CI.
- Strengthen build/test and review skills with scope, consumer, contract, and
  regression checks.
